# `str_alloc`：`abs_str::String` 的编解码支持

**日期**：2026-11-04
**分支**：`feat/str_alloc`
**结论**：`abs_denco` 新增可选 feature `str_alloc`。打开后，
`abs_str::str_alloc::String<A>` 与标准库 `String` 一样支持
`TrEncodable` / `TrDecodable` / `TrStrFromUtf8`；解码时 allocator 由
`TrAllocSource` 从 decoder 的 arena 投影——`String<Global>` 使用全局分配器，
`String<&'alloc A>` 借用 decoder 的 arena（例如 `BumpArena`）。

## 1. 背景

`abs_str` 提供了带 allocator 参数的字符串 `String<A: Allocator>`。denco 的
解码方向已经有 `TrAllocSource` 投影：容器与 `BumpString` 都通过它从
decoder 的 `&'alloc Alloc` 取得自己的 allocator。`abs_str::String` 沿用同一
机制即可，不需要改 `TrDecoder` / `Visitor` / 格式侧代码。

## 2. 实现

- `abs_denco/Cargo.toml`：新增可选依赖
  `abs_str = { git = ".../abs_str-rs.git", default-features = false,
  features = ["str_alloc"], optional = true }` 与 feature
  `str_alloc = ["dep:abs_str"]`；
- `abs_denco/src/de/str_alloc_.rs`：
  - `impl TrStrFromUtf8 for abs_str::str_alloc::String<CA>`，用
    `CA::alloc_from(alloc)` + `String::from_str_in`；
  - `impl TrDecodable for abs_str::str_alloc::String<CA>`，走
    `TrDecoder::decode_string_as`，与 `BumpString` 的结构一致；
- `abs_denco/src/ser/str_alloc_.rs`：`impl TrEncodable for
  abs_str::str_alloc::String<A>`，与 `String` 一样按 `str` 编码；
- `abs_denco/src/lib.rs`：feature 表补 `str_alloc` 一行；`x_deps` 在 feature
  打开时再导出 `abs_str`，便于下游命名类型；
- 格式侧（`mp_denco` / `json_denco`）无需改动：它们只依赖
  `decode_string_as<S>` 与 `TrStrFromUtf8`。

## 3. 默认关闭

`str_alloc` **默认关闭**（`default = []`），与 crate 文档「容器实现默认一个
都不开、保持最小可用面」一致；需要时显式开启：

```toml
abs_denco = { version = "0.1", features = ["str_alloc"] }
```

`abs_str` 依赖也关闭了它自己的默认 feature（`serde`），只保留 `str_alloc`
所需的能力，避免把 serde 带进 `abs_denco` 的依赖图。

## 4. 测试

新增 `denco_bumpalo/tests/str_alloc_.rs`（7 个用例）：

- `String<Global>` 在 MessagePack / JSON 上解码（`NoArena`）；
- `String<&BumpArena>` 在 MessagePack / JSON 上解码，`allocated_bytes()`
  增长，证明使用 decoder 的 arena；
- `String<Global>` 重新编码并再次解码（往返）；
- derive 结构体字段 `String<Global>` 的编解码；
- derive 结构体字段 `String<&'alloc BumpArena>`：字段共享 decoder 的 arena。

`abs_denco/tests/owned_.rs` 增加 `String<Global>: TrDecodableOwned` 的编译期
断言。

## 5. 验证

- `cargo test --workspace --all-features`：33 个测试块，158 passed / 0 failed /
  18 ignored（其中 `str_alloc_` 7 个）；
- `cargo clippy --workspace --all-targets --all-features -- -D warnings`：通过；
- `RUSTDOCFLAGS="-D warnings" cargo doc --workspace --all-features --no-deps`：通过；
- `abs_denco` 默认、`str_alloc`、`alloc-collections`、`cow`、`rc`、`std`
  分别 check / test：通过（`owned_` 的 `Cow` 断言已按 feature 门控）；
- `format_use_imports.py --check`：合规。

## 6. 已知限制

- derive 的 allocator 参数识别仍只覆盖标准容器的位置；`abs_str::String<A>`
  里的 `A` 若是结构体的泛型参数，derive 会把它当值参数处理。当前推荐写
  `String<Global>` 或具体生命周期形式 `String<&'alloc A>`（已有测试覆盖）。
- `abs_str` 的 `String` 位于 `abs_str::str_alloc::String`，不是 crate 根；
  denco 的 `x_deps` 只再导出 crate 本身。
