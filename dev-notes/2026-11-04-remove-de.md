# 彻底移除解码方向的 `'de`：让 `'alloc + Alloc` 成为唯一借用轴

**日期**：2026-11-04
**分支**：`exp/remove-de`（从 `main` = `9550d95` 切出）
**当前结论**：解码方向删除 `'de`，只保留 `'alloc`（arena 借用寿命）与 `Alloc`
（arena 类型）；删除 `Visitor::visit_borrowed_str` / `visit_borrowed_bytes`；
`TrDecodableOwned` 重定义为 `for<'alloc> TrDecodable<'alloc, NoArena>` 并保留。
本仓库内全部 trait / impl / derive 生成代码与示例同步迁移；下游
（`mptp_rpc`、`mptp_smux_v1`、`mptp_cs_smoke` 等）本轮不修，迁移指引见 §10。

## 1. 背景与现状证据

`'de` 是从 serde 继承下来的「反序列化结果借用输入数据」的寿命。denco 在
2026-11-02 的 allocator 重构中新增了 `'alloc`（`TrDecoder<'de, 'alloc, Alloc>`），
于是出现了两条借用轴：

- `'de`：结果借用**输入缓冲区**；
- `'alloc`：结果借用**调用者提供的 arena**。

对当前代码逐项核对后，`'de` 这一条轴没有实际语义：

1. **没有任何 producer。** `git grep -n visit_borrowed` 只命中
   `abs_denco/src/de/visitor_.rs` 的两个定义；`mp_denco` / `json_denco` 的
   字符串路径都走 `visit_str`（临时视图）或 `visit_string`（owned），从不调用
   `visit_borrowed_str` / `visit_borrowed_bytes`。
2. **格式实现没有把 `'de` 绑定到输入。** `MpDecoder` / `JsonDecoder` 都写成
   `impl<'de, 'alloc, 'r, R, A> TrDecoder<'de, 'alloc, A> for ...`，其中
   `'de` 与读端借用 `'r`、输入缓冲寿命都无约束关系；调用方可以任选 `'de`。
   它只是一个「占位」参数，不能给用户任何借用保证。
3. **没有 `TrDecodable for &'de str` / `&'de [u8]`。** 借用输入的解码实现
   从未落地；`&'alloc str` / `&'alloc [u8]` 走的是
   `decode_string_as` / `TrArenaBytes`（复制进 arena），与输入缓冲无关。
4. **未来也无法靠保留 `'de` 同时支持两种借用。** `impl TrDecodable for
   &'alloc str` 已经占用 `&str` 的目标类型；再写 `impl TrDecodable for &'de str`
   会在类型层面重叠（同一个 `&'x str` 同时匹配两个 impl），除非引入额外的
   目标类型包装。因此「保留 `'de` 以便将来支持输入借用」不是一个可选项。
5. **derive 已经把用户生命周期绑定到 `'alloc`。**
   `denco_macro/src/model_.rs::bound_lifetimes_to_alloc_` 把用户声明的所有
   生命周期替换为 `'alloc`，生成的 impl 形如
   `impl<'de, 'alloc, ...> TrDecodable<'de, 'alloc, __DencoAlloc> for Foo<'alloc>`；
   字段借用的是 arena，不是输入。`'de` 在生成代码里只是被透传的冗余参数。
6. **认知与实现成本。** 每个 `decode_*` 的 GAT、每个 helper future、每个
   `Visitor` / access impl、每个手写测试都要多写一个 `'de` 与 `'de: 'a`；
   而它既不产生行为差异，也无法被格式实现有意义地约束。

## 2. 目标 trait 形状

只保留 `'alloc + Alloc`；`'a` 仍是 GAT / RPITIT 的 future（或 visit）临时
寿命，**不删除**。

```rust

    type Error: Error;

    fn allocator(&self) -> &'alloc Alloc;

    type DecodeAnyAsync<'a, V>: TrMayCancel<'a, MayCancelOutput = Result<V::Value, Self::Error>>
    where
        'alloc: 'a,
        V: Visitor<'alloc, Alloc> + 'a,
        V::Value: 'a,
        Self: 'a,
        Self::Error: 'a;

    fn decode_any<'a, V>(self, visitor: V) -> Self::DecodeAnyAsync<'a, V>
    where
        'alloc: 'a,
        V: Visitor<'alloc, Alloc> + 'a,
        V::Value: 'a,
        Self: 'a,
        Self::Error: 'a;
```

`decode_string_as`、`TrArena`、`TrArenaBytes`、`TrAllocSource`、
`TrStrFromUtf8`、`BumpBox`、`BumpString` 的语义与行为全部不变，只去掉 `'de`
参数/约束。序列化方向（`TrEncodable` / `TrEncoder`）没有 `'de`，不动。

## 3. 三个生命周期与迁移规则

| 生命周期 | 含义 | 处置 |
| --- | --- | --- |
| `'de` | 结果借用输入数据 | 删除 |
| `'alloc` | 结果借用调用者 arena | 保留 |
| `'a` | GAT / RPITIT 的 future 或 visit 临时寿命 | 保留 |

逐项映射：

- `TrDecoder<'de, 'alloc, Alloc>` → `TrDecoder<'alloc, Alloc>`；
- `TrDecodable<'de, 'alloc, Alloc>` → `TrDecodable<'alloc, Alloc>`；
- `TrDecodableSeed<'de, 'alloc, Alloc>` → `TrDecodableSeed<'alloc, Alloc>`；
- `Visitor<'de, 'alloc, Alloc>` → `Visitor<'alloc, Alloc>`；
- 四个 access trait 及对应 `*Ext`：同上；
- `impl<'de, 'alloc, ...>` → `impl<'alloc, ...>`（彻底删除 `'de` 声明）；
- `where 'de: 'a` 整行删除，保留 `'alloc: 'a`；
- `V: Visitor<'de, 'alloc, Alloc> + 'a` → `V: Visitor<'alloc, Alloc> + 'a`；
- `D: TrDecoder<'de, 'alloc, Alloc> + 'a` → `D: TrDecoder<'alloc, Alloc> + 'a`；
- `T: TrDecodableSeed<'de, 'alloc, Alloc> + 'a` → `T: TrDecodableSeed<'alloc, Alloc> + 'a`；
- helper future 的泛型实参 `<'de, 'alloc, 'a, ...>` → `<'alloc, 'a, ...>`；
- `+ 'de` 这类「outlive 输入」约束：删除或改成 `+ 'alloc`。原则是
  **只保留能由 `'alloc: 'a` 传递出来的约束**；helper 内已有 `+ 'a` 的地方
  直接删 `+ 'de`，impl 层需要「字段/类型参数活到 arena」的地方写 `+ 'alloc`，
  其余依赖 trait GAT 的 `Self: 'a`。

禁止 `sed s/'de//`：文档里的 serde 对比、字符串、`quote!` 里的用户生命周期
片段都需要逐处判断。

## 4. `visit_borrowed_str` / `visit_borrowed_bytes` 的删除

- 两者是**输入借用**入口：`fn visit_borrowed_str(self, v: &'de str)` 的
  `'de` 就是「与输入同寿命」。删除 `'de` 后它们没有合法的参数类型，删除。
- `visit_str(&'a str)` / `visit_bytes(&'a [u8])` **保留**：`'a` 是本次 visit
  future 的临时视图寿命。`visit_string` / `visit_byte_buf` / `visit_char` 的
  默认实现正是在 future 内构造临时视图后转发到它们。
- 手写 visitor 若曾实现 `visit_borrowed_*`（本仓库内没有），迁移为
  `visit_str` / `visit_bytes`，或用 `decode_string_as` 从 arena 构造。
- 文档中的 `visit_borrowed_*` 示例删除；`Visitor` 的说明改为「借用字符串只能
  通过 `decode_string_as` 进入 arena，不存在输入借用入口」。

## 5. `TrDecodableOwned` 的处置

**决策：保留，重定义为**

```rust
pub trait TrDecodableOwned: for<'alloc> TrDecodable<'alloc, NoArena> {}
impl<T> TrDecodableOwned for T where T: for<'alloc> TrDecodable<'alloc, NoArena> {}
```

语义：**在任意 arena 寿命下都能用 `NoArena` 解出、且不借用 arena 的类型**。
`NoArena` 不实现 `TrArenaBytes`，所以 `&'alloc str` / `&'alloc [u8]` 不满足；
derive 把用户生命周期绑定到 `'alloc` 后，`Foo<'x>` 只实现
`TrDecodable<'x, ...>`，通常也不满足 `for<'alloc>`。

预期验证（实现后用编译断言确认）：

| 类型 | 是否满足 | 原因 |
| --- | --- | --- |
| `String` | 是 | impl 对任意 `'alloc` |
| `Vec<u32>` | 是 | `Global` 投影 + `u32` 均与 arena 无关 |
| `Cow<'a, str>` | 是 | impl 未把 `'a` 绑到 `'alloc`，解码恒为 `Owned` |
| `BumpString<Global>` | 是 | 同上，`Global` 投影 |
| `BumpBox<'alloc, T>` | 否 | `Self` 携带 `'alloc` |
| `&'alloc str` | 否 | 需要 `TrArenaBytes`，`NoArena` 不实现 |
| `Foo<'x>`（derive） | 否 | 用户生命周期被绑定为 `'alloc`，只有 `'alloc = 'x` 的 impl |

选择保留而不是删除的理由：

- 它是公开 API，删除同样破坏下游，但不带来额外收益；
- 重定义后的语义与名字「owned」仍然自洽：结果不借用 arena、也不借用输入；
- 下游若把它当作「任意输入都能解成 owned」的便捷约束，新定义恰好是
  可编译的精确版本（旧定义里的 `for<'de>` 本来就是空的）。

文档必须写清「`Foo<'x>` 这类带用户生命周期的类型通常不满足
`TrDecodableOwned`」，避免用户误以为它是所有 owned 类型的统称。

## 6. `Expected` 适配器

签名去掉 `'de`：

```rust
pub fn expected<'a, 'alloc, Alloc, V>(visitor: &'a V) -> impl Expected + 'a
where
    V: Visitor<'alloc, Alloc> + 'a,
    Alloc: TrArena<'alloc> + 'alloc;
```

`Visitor::expected(&self)` 的形状不变。文档中仍可保留「serde 的
`Visitor<'de>` 只有 `'de`」的对比文字，但 denco 的示例必须写成
`impl<'alloc, Alloc> Visitor<'alloc, Alloc> ...`。`expected::<Alloc, _>(&self)`
的 turbofish 写法不变（生命周期实参可省略）。

## 7. derive 生成代码的变化

`model_.rs` 的「用户生命周期绑定到 `'alloc`」策略**不变**；只删除 `'de` 注入：

- 泛型参数：`<'de, 'alloc, 'a, __DencoAlloc, ...>` → `<'alloc, 'a, __DencoAlloc, ...>`；
- impl：`impl<'de, 'alloc, __DencoAlloc, ...> TrDecodable<'de, 'alloc, __DencoAlloc>
  for Foo<'alloc>` → `impl<'alloc, __DencoAlloc, ...> TrDecodable<'alloc, __DencoAlloc>
  for Foo<'alloc>`；
- visitor：`impl<'alloc, __DencoAlloc> Visitor<'alloc, __DencoAlloc> for __Visitor<...>`；
- seed：`impl<'alloc, __DencoAlloc> TrDecodableSeed<'alloc, __DencoAlloc> for ...`；
- 所有 `'de: 'a` 谓词删除，保留 `'alloc: 'a`；
- 字段约束 `#ty: TrDecodable<'de, 'alloc, __DencoAlloc>` →
  `#ty: TrDecodable<'alloc, __DencoAlloc>`；
- 类型参数约束 `#param: TrDecodable<'de, 'alloc, __DencoAlloc> + 'de` →
  `#param: TrDecodable<'alloc, __DencoAlloc> + 'alloc`；
- helper async fn / GAT 的 future 实参同步缩减；
- 新增/调整 derive 测试：`LifetimeRecord<'alloc>`、`LifetimeEnum<'alloc>`、
  `Option<&'alloc str>` 仍可编译。

## 8. 行为不变清单

- `TrArena` / `TrArenaBytes` / `TrAllocSource` / `TrStrFromUtf8` /
  `decode_string_as` / `BumpBox` / `BumpString` 的运行时行为不变；
- `NoArena` 下 `&'alloc str` / `&'alloc [u8]` 仍不可解码（编译期），仍由
  `TrArenaBytes` 缺失保证；
- `BumpBox<'alloc, Borrowed<'alloc>>` 的寿命仍只跟随 arena，不跟随输入；
- `Cow` 解码仍恒为 `Owned`；
- `IgnoredAny`、取消模型、`gen_mcf2` 生成的 future 形状不变。

## 10. 对下游的破坏性影响（本轮不修）

所有显式写 `'de` 的下游代码都会编译失败：

- `TrDecoder<'de, 'alloc, A>` → `TrDecoder<'alloc, A>`；
- `TrDecodable<'de, 'alloc, A>` / `TrDecodableSeed<'de, ...>` → 去掉 `'de`；
- `Visitor<'de, 'alloc, A>`、`MapAccess` / `SeqAccess` / `EnumAccess` /
  `VariantAccess` 及其 `*Ext` → 去掉 `'de`；
- 自定义 `impl<'de, ...> TrDecoder for ...` / `Visitor for ...`：删除 `'de`
  泛型与 `'de: 'a` 约束；
- 手写 helper 里 `V: Visitor<'de, 'alloc, A>` → `V: Visitor<'alloc, A>`；
- `visit_borrowed_str` / `visit_borrowed_bytes` 的实现删除；
- `TrDecodableOwned` 的 HRTB 语义变化：带用户生命周期的类型不再自动满足。

已知受影响的下游（工作区核对）：

- `mptp_rpc/rpc_core_v1`、`mptp_rpc/rpc_svc_macro`、`mptp_rpc/rpc_demo`；
- `mptp_rpc/mptp_smux_v1_demo` / `mptp_smux_v1`；
- `mptp_cs_smoke`（含其 `.tmp` 展开快照，需重新生成）。

迁移到新形状后，下游的「输入缓冲寿命」应改成一个普通的函数级生命周期
（例如 `fn decode<'data>(bytes: &'data [u8])`），不再作为 trait 参数。

  - `abs_denco/tests/owned_.rs`：`TrDecodableOwned` 的编译期断言；
  - `denco_bumpalo/tests/owned_.rs`：`BumpString<Global>` 的断言；
  - `TrDecodableOwned` 文档里的 `compile_fail` 例（`&'static str` 不满足）。

### 13.2 实施中的关键点

1. **`'de: 'a` 不能简单删除。** 它原本承担「由 `T: 'de` 推出 `T: 'a`」的
   传递职责；现在改为 `+ 'alloc`，并在 helper 里保留（或在缺失时补上）
   `'alloc: 'a`，才能从 `T: 'alloc` 推出 `T: 'a`。只删不补会在
   `collect_.rs` / `impls_.rs` 触发 E0309。
2. **derive 的 `Punctuated::insert` 索引会 panic。** 删掉 `'de` 的 insert 后，
   原 `insert(1, 'alloc)` 在空列表上越界；必须把同一组连续 insert 重新编号为
   `0..n`。
3. **测试里的输入生命周期与 trait 参数同名。** 旧 helper 用 `'de` 同时表示
   「输入缓冲寿命」和 trait 参数；去掉 trait 参数后，输入侧直接省略为
   `&[u8]`，不需要再引入新名字。
4. **`TrDecodableOwned` 的 `for<'alloc>` 是真实约束。** `String` /
   `Vec<u32>` / `Cow<'static, str>` / `Option<Vec<u8>>` /
   `BumpString<Global>` 的编译期断言通过；`&'static str` 的
   `compile_fail` doctest 通过（`NoArena` 不实现 `TrArenaBytes`）。
   `Cow<'static, str>` 能通过，是因为它的 impl 没有把 `'a` 绑定到 `'alloc`。
5. **derive 的 `+ 'alloc` 是比旧 `+ 'de` 略强的约束**：类型参数必须活到 arena
   寿命。当前所有验收用例（含 `foreign_alloc_` 的泛型 allocator）都满足；
   若下游出现「类型参数比 arena 短」的用法，需要在该类型上手写 impl 或缩短
   arena 寿命。
